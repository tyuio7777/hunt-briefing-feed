# Hunt Briefing Feed

**Hunt: Showdown 1896의 소식을 한국어로 정리하고, Hunt Briefing 앱에 제공하는 공개 데이터 저장소입니다.**

공식 업데이트와 이벤트, 커뮤니티의 관심사, 루머·미확인 정보를 구분해 전달합니다. 브리핑 본문과 함께 주요 일정, 앱 업데이트 정보, 공지사항 등 앱에서 사용하는 공개 데이터를 배포합니다.

Hunt Briefing은 게임을 즐기는 사용자를 위한 비공식 팬 프로젝트입니다.

## 저장소의 역할

- **브리핑 배포:** 발행이 완료된 브리핑을 JSON과 HTML로 제공합니다.
- **발행 이력 관리:** 최신 발행 정보와 과거 브리핑 목록을 제공합니다.
- **공식 정보 정리:** 확인된 공식 발표와 주요 변경 사항을 별도 HTML 문서로 제공합니다.
- **일정 연동:** 브리핑에서 확인한 이벤트·드롭스·업데이트 등의 일정을 앱에서 활용할 수 있도록 제공합니다.
- **앱 운영 정보 제공:** 앱 버전, 업데이트 안내, 공지사항, 커뮤니티 연결용 공개 설정을 관리합니다.
- **앱 데이터 소스:** C# .NET MAUI 기반 Android 앱이 공개 파일을 읽어 화면에 표시합니다.

이 저장소는 공개 데이터를 배포하는 공간입니다. 앱 소스 코드, 개인 대화 기록, 사용자별 AI 분석 결과, 인증 정보와 생성 중간 자료는 배포 대상에 포함하지 않습니다.

## 제공하는 정보

| 구분 | 내용 |
|---|---|
| 공식 소식 | 개발사 발표, 패치·핫픽스, 이벤트, 보상 및 서비스 안내 |
| 커뮤니티 동향 | 플레이어 토론, 공략, 후기, 주요 관심사와 지역별 반응 |
| 루머·미확인 정보 | 추측, 확인되지 않은 주장, 후속 확인이 필요한 내용 |
| 영상·참고 자료 | 관련 영상과 내용을 더 확인할 수 있는 원문 링크 |
| 주요 일정 | 날짜가 확인된 이벤트, 드롭스, 업데이트, 점검 등의 일정 |
| 앱 운영 정보 | 최신 앱 버전, 변경 사항, 공지사항과 공개 연결 설정 |

공식 발표와 커뮤니티 해석은 구분합니다. 반복해서 언급되거나 관심을 많이 받은 내용이라도 공식적으로 확인된 사실과 동일하게 취급하지 않습니다.

## 최신 발행 상태와 조회 순서

`feed/latest.json`의 최상위 `status`로 발행 상태를 구분합니다.

| 상태 | 의미 |
|---|---|
| `empty` | 아직 제공할 최신 발행본이 없는 초기 상태 |
| `ready` | 최신 발행 정보가 준비되어 있으며 `issue` 객체로 발행본을 안내하는 상태 |

`ready` 상태에서는 `issue` 객체에 발행 ID, 제목, 발행 시각, JSON·HTML 주소 등 최신 발행본의 정보가 포함되어야 합니다.

클라이언트의 권장 조회 순서는 다음과 같습니다.

1. `feed/latest.json`을 조회합니다.
2. `status`가 `ready`인지 확인합니다.
3. `issue` 객체와 필요한 주소가 유효한지 확인합니다.
4. `issue.json_url` 또는 `issue.html_url`에서 발행본을 읽습니다.
5. 이전 브리핑이 필요하면 `feed/index.json`의 `issues` 목록을 사용합니다.

파일명이나 날짜만으로 최신 발행본을 추정하지 않습니다. 예정된 발행 시각이 지났더라도 실제 발행 정보와 문서가 준비되었는지 확인해야 합니다.

## 브리핑 작성·정보 구분 원칙

- **출처를 함께 제공합니다.** 주요 내용에는 확인에 사용한 원문 링크를 연결합니다.
- **사실과 해석을 구분합니다.** 공식 발표, 플레이어 의견, 작성자의 정리와 추론을 혼동하지 않도록 작성합니다.
- **정보의 시점을 구분합니다.** 기사 게시일, 이벤트 진행일, 업데이트 적용일을 같은 날짜로 취급하지 않습니다.
- **적용 조건을 유지합니다.** 이벤트·게임 버전·플랫폼·모드가 다른 정보를 현재 상황에 그대로 적용하지 않습니다.
- **불확실한 내용은 명시합니다.** 확인되지 않은 루머나 예상 일정을 확정된 정보처럼 표현하지 않습니다.
- **확인 범위를 과장하지 않습니다.** 조사한 자료에서 찾지 못한 내용을 곧바로 미공개·취소·삭제로 단정하지 않습니다.

브리핑은 발행 당시 확보한 자료를 바탕으로 작성됩니다. 이후 변경 사항이나 정정이 있을 수 있으므로 실제 참여 조건과 최신 적용 내용은 연결된 원문도 함께 확인해 주세요.

## 일정 데이터 관리 원칙

브리핑에서 확인한 일정은 날짜별 JSON의 최상위 `calendar_events` 배열에 기록합니다.

새 발행본에는 일정이 없더라도 빈 배열 `[]`을 유지하는 것을 원칙으로 합니다. 해당 필드가 없는 과거 발행본은 일정 데이터가 없는 것으로 처리합니다.

| 필드 | 의미 |
|---|---|
| `event_id` | 동일 일정을 식별하는 고정 ID |
| `title` | 일정 제목 |
| `summary` | 일정의 내용과 참여 조건 요약 |
| `start_date` | 시작 날짜 |
| `end_date` | 종료 날짜 |
| `source_url` | 일정을 확인한 원문 주소 |
| `status` | `confirmed`, `tentative`, `cancelled` |
| `start_at` | 정확한 시작 시각이 확인된 경우 기록 |
| `end_at` | 정확한 종료 시각이 확인된 경우 기록 |

일정은 다음 원칙으로 관리합니다.

- 이벤트 시작·종료, 드롭스, 업데이트 적용, 점검 등 **실제 일정이 확인된 항목**을 기록합니다.
- 기사나 브리핑이 발행된 날짜를 이벤트 날짜로 대신 사용하지 않습니다.
- 날짜가 불명확한 내용은 임의의 일정으로 생성하지 않습니다.
- 날짜만 공개된 경우 자정이나 예상 시간을 확정 시각으로 넣지 않습니다.
- 원문에 시간대가 명시되어 있으면 이를 기준으로 한국시간 날짜와 시각을 정리합니다.
- 정확한 시각은 시간대가 포함된 형식으로 기록하고 날짜 필드와 일치하는지 확인합니다.
- 동일 일정은 브리핑이 달라져도 같은 `event_id`를 유지합니다. 일정 변경이나 취소 시에도 ID를 유지합니다.

동일한 드롭스 캠페인이 여러 문서에 등장할 수 있습니다. 중복을 판단할 때는 제목뿐 아니라 대상 게임, 캠페인, 원문 주소, 시간대를 맞춘 시작·종료 시각을 함께 비교합니다.

**일정의 중복 정리와 브리핑 본문의 보관은 별도로 관리합니다.** 같은 일정이 포함되어 있더라도 서로 다른 브리핑의 다른 소식이나 출처 정보까지 삭제하지 않습니다.

## 발행·수정 시 확인 사항

- 날짜별 JSON과 HTML이 준비되었는지 확인합니다.
- 발행 ID, 제목, 발행 시각과 문서 주소가 서로 일치하는지 확인합니다.
- 출처 링크와 이미지 주소, 일정의 날짜·시간대·상태를 확인합니다.
- `feed/index.json`과 `feed/latest.json`이 실제 제공 가능한 발행본을 가리키도록 유지합니다.
- 최신 발행 정보만 먼저 변경해 앱이 아직 없는 문서를 조회하는 상황을 피합니다.
- 기존 발행본을 정정할 때는 연결된 목록과 메타데이터의 일관성도 확인합니다.

브리핑 발행, 공식 정보 문서 갱신, 앱 업데이트 안내는 서로 다른 데이터입니다. 한 종류의 파일이 변경되었다는 이유만으로 다른 종류의 새 발행이 발생한 것으로 판단하지 않습니다.

또한 공개 데이터의 갱신과 앱의 알림 수신은 별개입니다. 기기에서의 표시·알림 시점은 앱의 조회 주기, 사용자 설정과 실행 상태에 따라 달라질 수 있습니다.

## 데이터 형식과 호환성

`schema/briefing-v1.schema.json`은 브리핑 v1의 구조 정의입니다.

다만 **발행 시기와 운영 형식에 따라 실제 브리핑 JSON의 필드 구성이 다를 수 있으며, 현재 일부 발행본은 기존 v1 스키마와 구조가 다릅니다.**

새로운 클라이언트를 연결하거나 파서를 수정할 때는 스키마 파일만 전제하지 말고, 실제 발행 JSON과 사용하는 앱의 처리 형식을 함께 확인해 주세요.

스키마와 운영 데이터를 정비할 때는 다음 사항을 유지합니다.

- 기존 앱에서 사용하는 필드와 공개 주소의 호환성
- 과거 발행본의 조회 가능 여부
- 누락되거나 비어 있는 선택 항목에 대한 처리
- 날짜별 JSON·HTML과 최신 발행 정보의 연결 관계

구조가 맞지 않거나 필요한 필드가 없는 경우에는 정상적인 새 발행본으로 처리하지 않도록 합니다.

## 공개 데이터와 민감 정보

이 저장소에는 공개 배포가 가능한 완성된 콘텐츠와 앱 운영용 공개 설정만 저장합니다.

다음 정보는 저장하지 않습니다.

- API 키, 액세스 토큰, 인증 비밀값과 비밀번호
- 비공개 이메일 주소와 개인 식별 정보
- 사용자의 개인 대화·질문·분석 기록
- 내부 프롬프트와 생성 중간 자료
- 공개할 의도가 없는 운영 로그와 내부 설정

커뮤니티 연결에 필요한 **공개 Client ID나 저장소 식별자**는 공개 설정에 포함될 수 있습니다. 이를 인증 비밀값이나 사용자 액세스 토큰과 혼동하지 않도록 합니다.

## 오류·정정 요청

내용이나 일정에 오류가 있다면 해당 브리핑의 발행일 또는 파일 경로, 문제가 있는 항목, 확인 가능한 원문 링크를 함께 알려 주세요.

일정 관련 오류는 원문 시간대와 시작·종료 시각을 함께 제시하면 확인에 도움이 됩니다. 문의나 오류 보고에는 API 키, 토큰과 개인 정보를 포함하지 마세요.
